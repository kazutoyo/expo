ユーザーのデバイス上の位置情報や連絡先など、機密性の高い可能性がある情報へのアクセスを必要とするネイティブアプリを開発する場合、アプリは最初にユーザーに許可を求める必要があります。たとえば、ユーザーのメディアライブラリにアクセスするには、アプリで [`MediaLibrary.requestPermissionsAsync()`](/versions/latest/sdk/media-library#medialibraryrequestpermissionsasyncwriteonly-granularpermissions) を実行する必要があります。

スタンドアロンアプリと [開発ビルド](/develop/development-builds/introduction/) における権限は、ランタイムの JavaScript コードでリクエストする前に、ネイティブのビルド時設定が必要です。[Expo Go](https://expo.dev/go) アプリでプロジェクトをテストする場合、この設定は必要ありません。

> ネイティブの権限を適切に設定・説明しないと、**アプリがストアで却下されたり削除されたりする可能性があります**。

## Android

権限は、[app config](/ja/workflow/configuration/) の [`android.permissions`](/versions/latest/config/app/#permissions) キーと [`android.blockedPermissions`](/versions/latest/config/app/#blockedpermissions) キーで設定します。

ほとんどの権限は、アプリで使用しているライブラリによって、[config plugin](/config-plugins/plugins/#creating-a-config-plugin) を使うか、パッケージレベルの **AndroidManifest.xml** を使うかのどちらかで自動的に追加されます。ライブラリにデフォルトで含まれていない権限を追加したい場合にのみ、`android.permissions` を使う必要があります。

```json app.json
{
  "android": {
    "permissions": ["android.permission.SCHEDULE_EXACT_ALARM"]
  }
}
```

パッケージレベルの **AndroidManifest.xml** ファイルによって追加された権限を削除する唯一の方法は、[`android.blockedPermissions`](/versions/latest/config/app/#blockedpermissions) プロパティでブロックすることです。これを行うには、**権限のフルネーム** を指定します。たとえば、`expo-camera` によって追加される録音の権限を削除したい場合は、次のようにします。

```json app.json
{
  "android": {
    "blockedPermissions": ["android.permission.RECORD_AUDIO"]
  }
}
```

- デフォルトの [prebuild テンプレート](/ja/workflow/continuous-native-generation#テンプレート) にどの権限が含まれているかについては、[`android.permissions`](/versions/latest/config/app/#permissions) を参照してください。
- 正当な理由なく _dangerous_ や _signature_ の権限を使用しているアプリは、**Google によって却下される可能性があります**。アプリを申請する際は [Android の権限に関するベストプラクティス](https://developer.android.com/training/permissions/usage-notes) に従ってください。
- [利用可能なすべての Android `Manifest.permissions`](https://developer.android.com/reference/android/Manifest.permission)。

<ConfigReactNative>

特定の権限を除外するには **AndroidManifest.xml** を変更します。`<use-permission>` タグに `tools:node="remove"` 属性を追加すると、その権限がライブラリの **AndroidManifest.xml** に含まれていても確実に削除されます。

```xml
<manifest xmlns:tools="http://schemas.android.com/tools">
  <uses-permission tools:node="remove" android:name="android.permission.ACCESS_FINE_LOCATION" />
</manifest>
```

> `tools:node` 属性を権限に使用する前に、`<manifest>` に `xmlns:tools` 属性を定義しておく必要があります。

</ConfigReactNative>

## iOS

iOS アプリでは、ユーザーにシステム権限の許可を求めることができます。たとえば、デバイスのカメラを使ったり写真にアクセスしたりするには、そのデータをアプリがどのように利用するかについて Apple が説明を要求します。ほとんどのパッケージは、[config plugin](/config-plugins/introduction/) によって特定の権限に対する定型的な理由を自動的に提供します。これらのデフォルトのメッセージは、アプリが App Store に受理されるためには、多くの場合、自分のアプリのユースケースに合わせて調整する必要があります。

権限のメッセージを設定するには、[app config](/ja/workflow/configuration/) の [`ios.infoPlist`](/versions/latest/config/app/#infoplist) キーを使います。たとえば次のとおりです。

```json app.json
{
  "ios": {
    "infoPlist": {
      "NSCameraUsageDescription": "This app uses the camera to scan barcodes on event tickets."
    }
  }
}
```

これらのプロパティの多くは、それを追加するライブラリに関連付けられた [config plugin](/config-plugins/introduction/) のプロパティを使って直接設定することもできます。たとえば [`expo-media-library`](/versions/latest/sdk/media-library) では、次のように写真の権限メッセージを設定できます。

```json app.json
{
  "plugins": [
    [
      "expo-media-library",
      {
        "photosPermission": "Allow $(PRODUCT_NAME) to access your photos.",
        "savePhotosPermission": "Allow $(PRODUCT_NAME) to save photos."
      }
    ]
  ]
}
```

- **Info.plist** への変更は over-the-air アップデートで更新できません。新しいネイティブバイナリをサブミットしたときにのみ反映されます。たとえば [`eas build`](/build/introduction) を使った場合です。
- Apple 公式の [権限メッセージの推奨事項](https://developer.apple.com/design/human-interface-guidelines/privacy#Requesting-permission)。
- [利用可能なすべての **Info.plist** プロパティ](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CocoaKeys.html)。

<ConfigReactNative>

**Info.plist** ファイル内の権限メッセージの値を直接追加・変更します。オートコンプリートを利用できるため、Xcode で直接行うことをおすすめします。

</ConfigReactNative>

## Web

web では、`Camera` や `Location` のような権限は [secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts#When_is_a_context_considered_secure) からのみリクエストできます。たとえば `https://` や `http://localhost` を使う場合です。この制限は Android のマニフェスト権限や iOS の **Info.plist** の使用目的メッセージと似ており、プライバシーを高めるために課されています。

## 権限をリセットする

多くの場合、ユーザーが権限を拒否したときにアプリがどう振る舞うかをテストして、適切に対応できることを確認したいはずです。Android と iOS の両方には OS レベルの制限があり、アプリは同じ権限を複数回リクエストすることができません（権限を拒否したあとに何度も権限を求められたら、ユーザーにとってどれほど煩わしいか想像できるでしょう）。開発中に権限に関わるさまざまなフローをテストするには、ネイティブアプリをアンインストールして再インストールする必要がある場合があります。

[Expo Go](https://expo.dev/go) でテストする場合は、`npx expo start` を実行して [Expo CLI](/more/expo-cli/) のターミナル UI で <kbd>I</kbd> または <kbd>A</kbd> を押すことで、アプリを削除して再インストールできます。
